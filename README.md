# 医疗 AI 回答质量评测与 Prompt 实践（个人项目）

这份目录是我在整理医疗场景 AI 质量评测时陆续攒下的，不是公司项目，也没有一份真实病人数据。

## 为什么做这套东西

做这套东西之前，我一直在试用各类健康 AI。它们大多能把话说顺，但能不能安全、准确、完整地回应一个真实病情，差别很大。我的临床本科背景刚好能派上用场：医生判断病情，靠的不是背答案，而是“先排除危险、再考虑常见、说话留余地”。我试着把这套判断过程拆开，做成能交给模型和数据标注员执行的东西，于是有了下面两个部分：

1. `qa_eval_set/`：病历问答评测集，15 个虚构场景，每个都写了“合格回答必须覆盖什么”“模型容易在哪里翻车”。
2. `prompt_library/`：医疗 Prompt 案例库，10 组我反复改过的 Prompt，覆盖主问答、自动评分、病历质控、内容审核等场景。

放进来之前我自己又核过一遍：内容按公开的临床常规写，不是抄的哪份病历；边界上该说“去急诊”的地方都写了，没有让模型替医生开药。

## 这两个文件怎么配合用

先把评测集里的病历+问题丢给被测模型，拿它的回答对照每条的“必须覆盖点”打分，找出高频问题；再用 Prompt 库里的对应模板去改模型行为，改完拿同一批题回归。简单说就是“先测出问题，再写 Prompt 修，修完再测”。这套流程我后面也想写成一个小脚本，把打分结果存成 CSV，现在还没动手。

## 一句话介绍

> 自建医疗场景问答评测 15 条，覆盖胸痛分诊、发热皮疹、用药安全、心理危机等高风险主题，每条含合格回答要点、常见错误类别，并按安全/准确/完整/循证四档评分；配套编写医疗场景 Prompt 10 组，含自动评测、病历质控、RAG 引证、广告审核，每组记录设计理由与回归方法。

## 说明

- 所有病历均为虚构演示数据，只用来展示“怎么设计脱敏、怎么定评测标准”，不代表真实患者，也不能用于诊疗。
